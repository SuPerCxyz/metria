# Metria 设计标准

本文件定义前端与报告共用的视觉标准。**图表颜色必须引用 `web/chart-theme.json`，禁止在代码里硬编码 hex**（前端 `import`，Hub 报告 `include_str!` 同一文件）。

## 1. 颜色

### 1.1 单一来源

`web/chart-theme.json` 分两层：

- `palette`：8 色通用序列色板，按顺序分配给**没有固定语义**的多序列图（如模型趋势、Agent 趋势）。
- `colors`：**有固定业务语义**的颜色，跨页面、图表、报告渠道必须一致：
  - `colors.token`：Token 分类（输入 / 输出 / 缓存读取 / 缓存写入 / 推理）
  - `colors.metric`：单指标趋势强调色（费用 / 时长 / 请求数）
  - `colors.latency`：延迟分位（P50 / P95 / 平均）

### 1.2 Token 分类色（固定）

| 分类 | 色值 | 语义 |
|---|---|---|
| 输入 | `#6366f1` 靛蓝 | 非缓存输入 Token |
| 输出 | `#10b981` 绿 | 生成的输出 Token（**含推理**） |
| 缓存读取 | `#f59e0b` 琥珀 | cache read |
| 缓存写入 | `#06b6d4` 青 | cache write |
| 推理 | `#8b5cf6` 紫 | 输出的分解项（`其中推理`） |

### 1.3 规则

1. 图表颜色一律引用 `chart-theme.json`；新增图表先查 `colors`，没有对应语义才用 `palette`。
2. 同一分类在全站——页面、趋势图、堆叠图、总览、分析、详情、报告 HTML/PDF、邮件——必须同色。
3. 同一张图内不得复用同一色值；`palette` 中已被 `colors` 占用的色值不得再分配给其他序列。
4. 堆叠与图例顺序固定：输入 → 输出 → 缓存读取 → 缓存写入 → 推理；`值为 0 的固定分类不占图层`（非 0 时自动恢复）。
5. 浅色与深色主题都要可辨；对比度不足时调整明度，不换色相。
6. 色值必须来自 `palette`（用测试守卫：`web/src/components/charts/theme.test.js` 与 `crates/metria-hub/src/report/render.rs::token_colors_come_from_chart_theme`）。

## 2. 术语与展示

- 总 Token 称为「**Token 消耗**」，口径为 `输入 + 输出 + 推理 + 缓存读取 + 缓存写入`（含缓存）。
- 展示层的「输出」含推理；推理只作为「其中推理」的分解项出现，不参与相加。
- 指标名不使用「真实」等修饰词——面板上的数值都是真实采集值，单独强调某一个会让其余显得像估算。仅流量相关处按项目硬性规则显式标注「估算流量」。

## 3. 交互

- 顶栏刷新按钮：点击后图标持续旋转且按钮禁用，直到本次刷新触发的请求全部结束才恢复默认（图标回正、可再次点击）；带兜底——400ms 内无请求发起即结束、最长 15s 强制结束。
- 加载、空态与错误态沿用 `components/feedback` 的既有组件，不新造样式。

## 4. 变更流程

1. 改颜色：先改 `web/chart-theme.json`，前端与后端自动跟随；不要只改某一处。
2. 改语义或顺序：同步更新本文件与 `theme.test.js` 的期望值。
3. 视觉类改动完成后需截图核对浅色/深色主题，并在 lstable 上验收。
