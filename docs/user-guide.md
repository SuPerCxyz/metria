# 用户手册

本手册面向第一次使用 Metria 的管理员，覆盖从登录、接入 Agent 到查看用量和配置定时报告的完整流程。

## 1. 登录 Hub

启动 Hub 后打开 `http://<hub-address>:8080`。登录方式由部署配置决定：

- 未配置 OIDC：使用 `METRIA_ADMIN_USER` / `METRIA_ADMIN_PASSWORD` 初始账号；
- 配置 OIDC：登录页显示 OIDC 入口，并按白名单限制唯一允许账号；
- 首次部署后应立即修改默认密码，或在生产环境直接启用 OIDC。

## 2. 添加 Agent 节点

进入「节点 → 添加节点」，填写节点名称、平台、架构和连接方式。创建后页面会生成一次性 Token 与安装命令。

| 模式 | 适用场景 | 主要配置 |
|---|---|---|
| Push | Hub 可被 Agent 访问 | Agent 主动向 Hub 上传，默认无状态轮询 |
| Pull | Hub 在内网、Agent 在公网 | Hub 主动访问 Agent，Agent 保留本地 spool |

页面可生成以下安装方式：

- Docker Agent；
- Linux amd64/arm64 原生 Agent；
- Windows amd64 原生 Agent。

Agent 只读挂载 Claude Code、Codex、OpenCode 的数据目录，不修改客户端配置、日志或数据库。节点显示为在线后，Hub 会开始接收增量数据。

完整网络、挂载和 OIDC 配置见 [部署指南](deployment.md)。

## 3. 查看总览

总览页按时间范围和节点筛选显示：

- Token：输入、输出、缓存读、缓存写和推理 Token；
- 费用：上报费用、计算费用和估算费用；
- 估算流量：总量、下界、上界和估算来源；
- 调用、会话、成功率、在线节点和 Agent 状态；
- Token 趋势、模型排行和 Agent 排行。

## 4. 理解费用和流量

Metria 不把不同来源的数据混成一个不可追溯的数字：

- `reported`：客户端或服务端直接上报的值；
- `calculated`：根据价格目录或用户规则计算的值；
- `estimated`：缺少直接费用时的估算值；
- 估算流量：根据可见内容、Token 和版本化 Profile 估算，不等同于网卡或账单流量。

缺失 Token 使用 `null`，不会为了填满图表而默认写成 0。没有足够数据时，界面会显示不可用或缺失口径。

价格规则和流量 Profile 的修改不会覆盖历史快照；如需重新计价或重新估算，系统会保留新旧结果。

## 5. 配置定时用量报告

进入「设置 → 用量报告」。报告配置保存在 Hub 的 SQLite 中，不需要修改 Agent。

### 5.1 时区和调度

全局时区同时用于 Web 展示、报告分桶和调度。设置页保存的时区优先于 `METRIA_TIMEZONE` 环境变量。

三个调度相互独立，可以只启用其中一个，也可以同时启用：

- 每日：汇总上一自然日；
- 每周：汇总上一自然周，并选择周一至周日；
- 每月：汇总上一自然月，并选择 1–28 号。

### 5.2 邮件和 Webhook

- 邮件使用 SMTP，支持明文、STARTTLS 和 SSL/TLS；
- 收件人可以填写多个邮箱，留空时尝试解析 OIDC 登录邮箱；
- Webhook 使用通用 JSON，可配置自定义 Header 和 `X-Metria-Secret`；
- 邮件包含 HTML 和纯文本正文；启用图表后，趋势图以 SVG 内嵌在 HTML 中；
- PDF 当前不会作为邮件附件发送。

报告只包含汇总指标、排行和估算流量，不包含会话正文、提示词或代码。请确认 SMTP 收件人和 Webhook 地址可信。

### 5.3 测试发送和失败处理

点击「发送测试邮件/Webhook」可以立即按当前配置测试启用的渠道。测试发送不会占用自动调度周期。

自动调度对同一个 `类型 + 周期` 只执行一次尝试。即使投递失败，本周期也不会持续重复发送；修复配置后可以手动测试，下一周期会重新发送。

单个渠道成功时，结果区域只显示一次成功状态；同时启用多个渠道或出现失败时，页面会显示各渠道结果和错误详情。

### 5.4 发送历史

Hub 只保留最近 30 条发送记录，设置页每页展示 10 条。历史包含时间、周期、渠道、状态和错误详情，可用于确认 SMTP 或 Webhook 的实际投递结果。

## 6. 常用设置

- 「模型价格」：查看目录、添加用户规则和重新计价；
- 「数据保留」：查看当前内容保存模式和相关状态；
- 「节点接入」：管理节点身份、安装命令和 Agent 地址；
- 「系统设置」：修改管理员资料、密码和其他系统级选项。

## 7. 常见问题

### 页面没有数据

先确认 Agent 节点为在线状态，再检查客户端目录是否只读挂载到正确位置。可以在目标节点执行 `metria doctor --adapter` 和 `metria doctor --hub`。

### 费用为空或显示估算

这是数据诚实性设计：客户端没有上报费用且没有匹配价格规则时，不会伪造费用。请在「模型价格」中补充规则或同步价格目录。

### 流量不是精确网卡流量

Metria 只根据日志、消息和 Usage 做流量估算，不抓包、不拦截 TLS，也不修改客户端网络链路。所有相关数字都应理解为估算范围。

### 报告发送失败

检查 SMTP 主机、端口、TLS 模式、发件人和收件人，或检查 Webhook URL 与网络连通性。修复后点击测试发送；自动调度不会在同一周期内无限重试。
